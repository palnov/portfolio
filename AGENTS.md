# Инструкции для агентов

Перед изменениями, которые затрагивают публикацию, прочитайте
[DEPLOYMENT.md](DEPLOYMENT.md). В нём описаны production-ресурсы Coolify,
маршрутизация кейсов через /cases, порядок проверки деплоя и правила добавления
новых проектов в портфолио.

Короткие обязательные правила:

- Production публикуется из ветки main через два Coolify-ресурса:
  portfolio-cms и portfolio-cases.
- Секреты не попадают в Git. Локальный SSH-файл
  .server-access.local.md уже добавлен в .gitignore; не выводите его содержимое
  в логи, diff или сообщения.
- Перед коммитом проверяйте git status --short и git diff --check и добавляйте
  только файлы текущей задачи.
- После push проверяйте статус конкретного Coolify deployment и публичные
  ответы. Для кейса обязательны HTTP 200 у HTML, CSS и JS.
- Не удаляйте Docker volumes, PostgreSQL или Coolify-ресурсы для исправления
  обычной ошибки сборки.

Правила из AGENTS.md во вложенных папках применяются к файлам внутри этих папок.
